# Instagram 评论清理器悬浮面板交互实现方案

## 1. 文档信息

- **状态**：待实现方案
- **适用范围**：Instagram 帖子和 Reels 页面中的清理器控制面板
- **编写日期**：2026-08-25
- **关联代码**：`src/content/social-comment-cleaner.js`

## 2. 背景与目标

当前内容脚本在目标帖子页直接创建右下角完整控制面板。面板没有最小化和关闭入口，运营人员无法在不刷新页面的情况下收起或移除控件；重新打开同一帖子标签页时，面板还会再次出现。

本方案将现有面板改为“右侧边缘标签入口 + 右下角完整面板”的两级悬浮控件：

1. 页面默认只显示清理器标签入口，减少对 Instagram 评论区的遮挡。
2. 单击标签入口打开完整面板，面板中的业务内容与当前版本保持一致。
3. 面板增加最小化按钮和关闭按钮。
4. 长按标签入口可沿屏幕边缘移动，松开后吸附到最近边缘。
5. 关闭运行中的控件前必须确认；确认后先暂停任务并保存进度，再退出当前页面控件。

## 3. 非目标

- 不改动评论筛选、回复优先、作者保护、白名单、关键词和删除确认逻辑。
- 不改变预览只扫描、不删除的行为。
- 不新增后台 API，不读取 Instagram 私有接口，不改变现有任务锁和会话检查点格式。
- 不把控件关闭状态同步到其他标签页；关闭状态只保存在当前标签页的 `sessionStorage`，刷新后继续保持关闭。
- 本期不实现自由拖动到页面任意位置，只允许在屏幕边缘吸附。

## 4. 用户界面方案

### 4.1 默认边缘标签入口

目标帖子页加载后创建一个 Shadow DOM 宿主，默认显示贴在右侧边缘的标签式入口。入口保留扩展现有 Logo，并使用半露出的胶囊标签外形；距离视口安全边界保留 8～16px。

默认状态示意：

```text
┌──────────────────────────────────────┐
│              Instagram 页面           │
│                                      │
│                          ┌─ 清理器   │ ← 标签式入口
└──────────────────────────────────────┘
```

Logo 需要满足：

- 具有可见的悬浮阴影和内侧圆角背景，外侧贴住视口边缘，确保在 Instagram 深色或浅色主题中可识别。
- 默认只露出标签的一部分，避免遮挡评论；鼠标悬浮或键盘聚焦时平滑露出完整标签。
- 尺寸参照页面内翻译插件：核心胶囊约 `36×36px`，外层交互区域约 `36×44px`，图标约 `18px`；不显示额外文字，避免入口过大。
- 设置 `role="button"`、`tabindex="0"` 和中文 `aria-label`。
- 支持鼠标、键盘 Enter/Space 和触控板 Pointer Events。
- 不阻断 Logo 之外的页面点击、滚动和文本选择。

### 4.2 标签入口悬浮关闭入口

鼠标悬浮或键盘聚焦标签入口时显示关闭图标；离开后隐藏关闭图标。关闭图标与入口分离，避免用户把“打开面板”误点成“关闭”。

```text
                             × ← 关闭当前页面控件
                    ┌─ 清理器 ← 点击打开面板
```

关闭图标与完整面板标题栏中的关闭按钮共用同一个关闭流程。

### 4.3 完整面板

单击 Logo 后，在右下角展开当前控制面板。面板业务内容必须保持现状，包括：

- 状态：空闲、扫描中、运行中、暂停、完成、错误等。
- 累计一级评论、累计回复、命中、待处理、删除、跳过统计。
- 连续加载状态、加载轮次、本轮新增、无新增重试次数。
- 当前等待原因、下一轮刷新倒计时和最近错误。
- `开始`、`暂停`、`停止`、`预览模式`四个现有操作按钮。

标题栏调整为：

```text
社交评论清理器                         —  ×
```

- `—`：最小化，回到右侧边缘 Logo，任务不受影响。
- `×`：关闭当前页面控件；运行中需要确认。

面板仍使用现有 Shadow DOM，宽度保持约 340px，固定在 `right: 16px; bottom: 16px`，层级保持在页面内容之上但不改变 Instagram 原有 DOM。

## 5. 交互状态机

### 5.1 控件状态

| 状态 | 显示内容 | 进入方式 | 退出方式 |
| --- | --- | --- | --- |
| `launcher` | 右侧边缘 Logo | 页面初始化、面板最小化 | 单击 Logo、关闭当前页面 |
| `hovering` | Logo + 关闭图标 | 鼠标悬浮或键盘聚焦 | 离开、失焦、点击其他操作 |
| `expanded` | 完整右下角面板 | 单击 Logo、开始/预览消息 | 最小化、关闭 |
| `dragging` | 正在移动的 Logo | 长按达到阈值并发生位移 | 松开指针、取消拖动 |
| `confirming-close` | 完整面板 + 确认框 | 运行中点击任一关闭入口 | 取消或确认关闭 |
| `closed` | 当前页面不显示任何清理器控件 | 空闲直接关闭，或确认暂停后关闭 | 配置页发送开始/预览消息，或打开新的标签页 |

### 5.2 任务状态与关闭行为

以下状态视为“任务正在运行”：`expanding`、`stabilizing`、`scanning`、`loading`、`waiting-load`、`running`、`waiting-delete`、`cooling-down`、`scheduled-rest`。

| 任务状态 | 点击关闭 | 结果 |
| --- | --- | --- |
| 空闲、已暂停、已完成、错误 | 不弹确认 | 立即移除当前页面控件 |
| 任一运行中状态 | 弹出确认框 | 取消则保持；确认则暂停并移除控件 |

确认框文案：

> 当前任务正在运行，关闭后将暂停任务并退出当前页面控件。确定关闭吗？

按钮：

- `取消`：关闭确认框，不改变任务和面板。
- `关闭并暂停`：调用现有 `pause()`，保存 `paused` 检查点、取消自动刷新、取消加载等待并释放目标帖子锁；暂停成功后移除 Logo 和面板。

如果暂停失败，控件不得移除，应在面板错误区域显示失败原因，要求用户使用“暂停”或“停止”按钮处理。

## 6. 长按移动与边缘吸附

### 6.1 点击和长按判定

- `pointerdown`：记录起点、指针 ID 和开始时间，启动约 500ms 的长按计时器。
- 500ms 内未发生明显位移时，保持点击候选。
- 位移超过 6px 或长按计时器完成后进入 `dragging`，调用 `setPointerCapture()`。
- `pointerup`：未进入拖动时视为单击并打开面板；进入拖动时计算吸附位置，不打开面板。
- `pointercancel`、窗口失焦或 Escape：取消拖动并恢复拖动前位置。

拖动期间设置 `user-select: none`，阻止 Instagram 页面文本选择；事件只在 Shadow DOM 控件内部处理，不向页面派发业务点击事件。

### 6.2 吸附算法

1. 读取 Logo 拖动结束时的中心点和视口宽高。
2. 计算其到上、下、左、右四条边的距离。
3. 选择最近的一条边。
4. 将 Logo 的对应坐标限制在安全边距和视口范围内。
5. 使用 160～220ms 的过渡动画吸附到边缘。

右侧边缘是默认位置；用户拖动后可以吸附到左、上、下边缘。窗口尺寸变化、浏览器缩放和移动端触控时重新限制坐标，不能让 Logo 离开视口。

本期位置只保存在当前内容脚本实例中，刷新页面后恢复默认右侧位置；不写入全局设置，避免一个页面的布局偏好影响其他标签页。

## 7. 与现有运行时的衔接

### 7.1 内容脚本改造

在 `src/content/social-comment-cleaner.js` 内将当前单一 `panel()` 拆分为以下职责：

- `createLauncher()`：创建边缘 Logo 和悬浮关闭入口。
- `openPanel()`：创建或显示完整面板。
- `minimizePanel()`：隐藏完整面板，恢复 Logo。
- `requestClose()`：根据任务状态决定直接关闭或显示确认框。
- `confirmClose()`：暂停任务、保存检查点并移除当前页面控件。
- `beginLauncherDrag()` / `finishLauncherDrag()`：处理长按、拖动和边缘吸附。
- `draw()`：继续只更新完整面板中的现有统计和状态节点；面板隐藏时不访问不存在的节点。

运行对象增加以下 UI 字段，不进入任务检查点：

```text
uiMode: 'launcher' | 'expanded' | 'dragging' | 'confirming-close' | 'closed'
launcherPosition: { edge, offset }
drag: { pointerId, startX, startY, startAt, moved, timer }
```

### 7.2 启动和恢复

- 页面初始化：如果当前标签页没有关闭标记，只创建边缘标签入口；已关闭的标签页刷新后不再创建控件。
- 配置页发送 `ICC_START` 或 `ICC_PREVIEW` 后，内容脚本先 `openPanel()`，再沿用现有启动流程。
- 从任务检查点自动恢复时，默认恢复边缘标签入口；如果任务进入运行状态，面板可以由用户单击入口打开。若标签页之前已关闭，任务仍可安全恢复但不显示控件。
- 配置页发送 `ICC_START` 或 `ICC_PREVIEW` 时清除当前标签页关闭标记并重新打开面板。
- 最小化不清除 `run` 中的任务状态；关闭确认后由现有 `pause()` 负责安全暂停。

### 7.3 后台脚本

本次不新增 Service Worker 消息。暂停、保存会话、取消刷新和释放锁全部复用现有 `ICC_PAUSE`、`ICC_SAVE_SESSION`、`ICC_CANCEL_REFRESH` 与锁管理流程。

## 8. 安全与异常处理

- 关闭确认框必须使用 Shadow DOM 内的自定义弹层，避免浏览器原生 `confirm()` 阻塞页面并造成样式不一致。
- 关闭按钮不能绕过暂停流程直接删除任务会话。
- 最小化不能暂停、停止、清空候选或释放锁。
- 扩展上下文失效时，控件关闭仍应安全完成；任务通信错误显示在面板错误区域。
- 页面进入验证、限流、权限不明确或 DOM 结构异常时，沿用现有暂停策略；悬浮控件只负责展示和控制，不改变扫描安全边界。
- 所有按钮必须有中文 `aria-label`，关闭确认框打开时焦点进入“取消”按钮，Escape 等同于取消。

## 9. 测试与验收

### 9.1 静态和单元测试

新增面板状态纯函数测试，至少覆盖：

1. 初始状态为 `launcher`。
2. Logo 单击进入 `expanded`。
3. 最小化从 `expanded` 回到 `launcher`，任务状态不变。
4. 短按不会进入拖动；长按并位移后进入 `dragging`。
5. 拖动结束后总能吸附到四条边之一，坐标不超出视口。
6. 空闲关闭立即进入 `closed`。
7. 运行中关闭先进入 `confirming-close`；取消不改变任务；确认调用暂停后进入 `closed`。
8. 暂停失败时保留控件并显示错误。
9. 现有面板统计、开始、暂停、停止和预览按钮仍正常绑定。

执行：

```bash
node --check src/content/social-comment-cleaner.js
npm test
git diff --check
```

### 9.2 Chrome 手动验收

使用测试账号和小批量测试评论验证：

1. 打开目标帖子，页面只出现右侧 Logo，不出现完整面板。
2. 单击 Logo，完整面板出现在右下角，原有内容和统计格式不变。
3. 鼠标悬浮 Logo，关闭图标出现；移开后关闭图标隐藏。
4. 长按 Logo 并拖到不同方向，松开后吸附到最近边缘；短按仍能打开面板。
5. 面板最小化后回到 Logo，预览或正式任务继续执行。
6. 空闲时关闭，当前页面入口和面板都消失；刷新页面后仍保持关闭，发送开始/预览消息后重新出现。
7. 运行中关闭，确认框正确出现；取消不影响任务，确认后任务暂停并移除控件。
8. 重新打开其他标签页时出现独立 Logo，不继承上一标签页的关闭状态或位置。
9. 预览模式不打开删除菜单、不申请删除额度；正式运行的暂停、停止和会话恢复行为与改造前一致。

3. 接入现有 `pause()`、检查点保存、锁释放和错误展示。
4. 调整页面初始化、开始/预览消息和自动恢复时的显示状态。
5. 更新 README 与运营人员操作手册，说明最小化、关闭确认和拖动吸附。
6. 执行静态测试、单元测试、打包检查，再进行 Chrome 手动验收。
