# TikTok 评论删除功能阶段 5 验收记录

> 阶段范围：实现评论分页并接入既有持续运行
>
> 记录日期：2026-09-03

## 实现范围

- `src/platform/tiktok/loader.js` 新增当前 `CleanerRuntime` 分页契约所需的 `createPagination()`、`loadNextBatch()`、进度快照、结束判定和 `cancel()`；插件只返回标准分页状态，不创建 TikTok 专属任务循环或刷新定时器。
- 分页先接受唯一且可见的页面级“加载更多评论”入口；没有入口时，只滚动唯一评论滚动容器。评论行和一级评论线程内的“查看/还有 N 条回复”入口被明确排除，仍由逐父评论展开流程处理。
- 每个批次在动作前后通过 TikTok 评论稳定键集合确认增长；评论容器被虚拟列表替换时重新发现评论面。重复入口、无法重新发现评论面、连续无增长但仍有可操作入口或待展开回复均会暂停。
- 仅在连续无新增、评论面处于末尾、没有页面级加载入口且没有待展开回复时返回 `completed && newIds === 0`。随后由通用 `CleanerRuntime.finishCurrentRound()` 保存检查点、安排随机休息和刷新恢复。
- TikTok 插件现在声明 `supportsAutoLoad: true`；页面模块仍全部在 `plugin.js` 前加载。后台、设置页和核心没有引入 TikTok DOM、专属定时器或刷新调度。

## 实际页面只读探测

对用户提供的 TikTok Web 作品页进行了只读页面结构探测，未点击回复入口、加载入口、菜单、删除或确认动作：

- 当前评论面中存在唯一可滚动的评论容器；页面整体的内容流与该评论容器可区分。
- 可见的“还有 N 条回复”位于单个一级评论线程下，属于回复展开而非页面级评论分页。
- 探测时未发现可操作的页面级“加载更多评论”入口，因此实际分页将走评论容器滚动分支。

该探测只确认 DOM 证据，不能证明多批加载、末页判断、随机休息、Alarm 刷新或检查点恢复已在真实测试账号上完成。
