# Instagram 评论 DOM-only 运行方案

## 目标

清理器只读取 Instagram 当前帖子页面已经渲染的评论 DOM，不改写 `fetch`、`XMLHttpRequest`，也不解析评论接口响应。这样不会锁定视频播放器使用的 `ReadableStream`，筛选数据与用户看到的评论保持一致。

## 运行边界

1. 扫描前等待可见的 `/c/<comment-id>/` 链接出现。
2. 在当前评论容器内按界面语言点击“查看回复/隐藏评论/加载更多评论或回复”等入口；入口可能只有子 SVG 的 `aria-label/title`，不能只读取按钮自身文本。
3. 等待评论容器经过 MutationObserver 和多帧确认后，从评论行 DOM 提取评论 ID、作者和文本。
4. 仅当前页面已经渲染的回复进入关键词筛选；一级评论不删除，帖子作者和白名单继续优先保护。
5. 删除前按评论 ID 重新定位 DOM，使用评论行菜单；删除后等待节点消失和容器稳定，再重扫。

## 不处理的内容

- 不拦截或克隆任何媒体、GraphQL 或评论接口响应。
- 不主动请求接口，不根据未渲染的 JSON 猜测评论。
- 不主动滚动评论列表；只点击当前可见的加载入口，并等待新的评论 ID 出现。没有可见入口时，用户手动加载更多评论后重新启动扫描。

## 验证

在目标帖子上，视频播放错误与评论扫描相互独立；预览统计来自页面当前可见评论行。若评论尚未展开，预览会先展开入口并等待 DOM 稳定，而不是等待接口响应。
