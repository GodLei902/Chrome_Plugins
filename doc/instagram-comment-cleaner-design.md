# Instagram 评论清理功能设计

## 目标与范围

本期为 Chrome 扩展实现 Instagram 评论清理能力。扩展仅在当前浏览器已登录的 Instagram 会话中操作页面 UI，不读取或上传账号凭据，不调用非公开接口。

功能范围如下：

- 仅处理配置中指定的一条 Instagram 帖子或 Reels。
- 按删除关键词筛选一级评论和回复。
- 按用户名精确匹配白名单；白名单始终优先于删除规则。
- 删除一级评论下的回复，并在必要时展开当前可见评论线程中的回复。
- 提供开始、停止、状态与统计控制；开始后自动扫描、删除、冷却和刷新。
- 通过单线程操作、随机等待、批次上限、会话上限与异常暂停降低误操作和高频动作风险。

本期不实现 TikTok、YouTube、Facebook，也不做无限滚动、跨页评论抓取或绕过 Instagram 的限制和验证。

## 评论规则

### 目标帖子

只有当前页面规范化后的 URL 与配置中的目标 URL 完全相同时才运行。规范化应忽略查询参数、哈希和结尾斜杠，但必须保留帖子类型和短代码；支持 `/p/<shortcode>/` 与 `/reel/<shortcode>/`。

### 白名单与关键词

- 白名单一行一个用户名，忽略大小写、首尾空白和可选的 `@` 前缀。
- 删除关键词一行一个普通文本，评论文本包含任一关键词即命中；关键词匹配忽略大小写与首尾空白。
- 未配置删除关键词时，仅扫描并展示候选数量，不执行删除。空规则不得解释为删除所有非白名单评论。
- 白名单用户名的评论永不删除，即使其评论文本命中关键词。

### 一级评论与回复

扫描当前打开的评论区域以及扩展在当前可见线程中展开后已加载的回复；不通过无限滚动或分页加载更深的评论列表。

删除顺序为先回复、后一级评论。删除一级评论可能导致其全部回复一并消失，因此当一个候选一级评论存在任意已加载的白名单回复时，必须跳过该一级评论。一级评论本身在白名单中不阻止删除其命中的非白名单回复，因为删除回复不会删除父评论。

如果 Instagram 菜单中没有该评论的删除项，说明当前账号没有对应管理权限或页面结构无法可靠识别；扩展应跳过该条并记录原因，不能猜测或点击其他菜单动作。

## 运行与状态

内容脚本维护以下状态：`idle`、`scanning`、`running`、`cooling-down`、`paused` 和 `error`。

```text
开始 / 预览模式
  -> 校验目标 URL、关键词和 Instagram 页面状态
  -> 扫描一级评论与已加载回复
  -> 预览模式：展示候选数并结束
  -> 开始：单线程逐条删除
  -> 冷却或刷新当前帖子
  -> 重新扫描，直到用户停止、达到会话上限或出现异常
```

开始按钮仅启动当前目标帖子的运行会话。停止按钮必须立即取消后续等待，并在每一次菜单点击、删除确认和刷新之前检查停止标记，因此停止后不会再启动下一条删除。

刷新前将运行会话、目标 URL、统计数据和下次扫描时间写入扩展本地存储；页面刷新后的内容脚本仅在该会话仍标记为运行、URL 仍匹配时恢复扫描。后台 Service Worker 维护按目标 URL 加锁的单实例租约，避免同一帖子在两个标签页中同时删除。

## 风控与异常处理

默认参数采用保守节奏，可在设置页的高级选项中调整，但所有时间值必须大于零：

| 参数 | 默认值 |
| --- | --- |
| 单条删除间隔 | 随机 12-25 秒 |
| 每轮最大删除数 | 3 条 |
| 每轮冷却时间 | 随机 120-300 秒 |
| 刷新检测间隔 | 随机 3-7 分钟 |
| 单次会话最大删除数 | 30 条 |
| 单次会话最长运行时间 | 2 小时 |

所有删除严格串行。遇到“请稍后重试”、操作受限、网络失败、验证或挑战页面、连续两次找不到删除确认按钮、或 Instagram DOM 选择器失配时，立即转为 `paused` 并显示原因，等待用户手动恢复。不得自动关闭限流提示后继续删除。

## 交互与设置

设置页提供目标帖子 URL、白名单用户名、删除关键词和高级频率设置；“开始”右侧的“预览模式”按钮只计算候选评论并展示统计，不进入删除菜单。

在 Instagram 目标帖页面注入独立 Shadow DOM 控制面板，避免被 Instagram 样式污染。面板包含开始、预览模式与停止按钮，并显示当前状态、扫描数、删除数、跳过数、下一次运行时间和最近一次错误。真实删除前，面板必须显示本轮候选数量并要求二次确认。

Instagram 界面会随语言和版本变化。评论、更多操作、删除菜单和确认弹窗的选择器应集中在 Instagram 适配器中，优先使用 ARIA 标签、角色和稳定的可见文本候选；找不到可靠元素时暂停而不是采用宽泛选择器。

## 模块边界

- 规则模块：用户名规范化、关键词匹配、白名单优先级、父评论级联保护和候选排序；应保持为可独立测试的纯函数。
- Instagram 内容适配器：收集当前可见评论与回复、展开回复、定位操作菜单、发起删除并验证 UI 已更新。
- 内容脚本运行器：URL 守卫、状态机、Shadow DOM 控制面板、延迟调度、刷新恢复和停止信号。
- 后台 Service Worker：跨刷新运行快照、单标签执行租约和运行统计协调。
- 设置页：读取并自动保存规则与频率参数；点击“开始”或“预览模式”时校验配置并启动当前目标帖子的对应运行会话。

当前脚手架中的 `src/content/social-comment-cleaner.js`、`src/background/service-worker.js` 和 `src/options/` 是上述实现的主要落点。

## 参考实现

- [1igaming/tampermonkey-instagram-comment-delete](https://github.com/1igaming/tampermonkey-instagram-comment-delete)：借鉴开始/停止、页面等待、删除确认和 UI 异常处理；其目标是删除“自己的活动评论”，不复用其全量选择逻辑。
- [sbolel/instagram-comment-activity-deleter](https://github.com/sbolel/instagram-comment-activity-deleter)：借鉴可测试的 DOM 自动化、超时处理、运行统计与预览模式。
- [iamceeso/instagram-bulk-comment-deleter](https://github.com/iamceeso/instagram-bulk-comment-deleter)：借鉴 Instagram Bloks UI 和 React 删除确认弹窗的交互方式。

这些参考项目均不具备本功能要求的目标帖子约束、用户名白名单、关键词筛选和父子评论保护，因此本项目需要独立实现评论识别与规则引擎。

## 验收场景

1. 当前 URL 不匹配、扩展未启用或关键词为空时，不产生删除操作。
2. 白名单一级评论与白名单回复都不会删除；带白名单回复的候选一级评论会被跳过。
3. 命中关键词的一级评论和回复可分别删除，未命中关键词的评论保持不变。
4. 预览模式仅显示候选和跳过统计，不打开删除菜单。
5. 停止按钮在两次删除之间立即生效，不会删除下一条评论。
6. 达到每轮上限后进入冷却；刷新页面后可根据持久化会话继续扫描。
7. 没有删除权限、确认弹窗缺失、限流提示、挑战页或页面结构变化时，运行自动暂停且保留错误信息。
8. 使用测试账号和临时评论先完成预览验证，再验证真实删除、统计和会话上限。
