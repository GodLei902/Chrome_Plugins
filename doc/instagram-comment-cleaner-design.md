# Instagram 评论清理器与操作节奏控制器设计

## 目标与范围

本期为 Chrome 扩展实现 Instagram 指定帖子或 Reels 的评论清理能力，并为实际删除操作加入操作节奏控制器（Action Pace Controller）。扩展只通过当前浏览器已登录的 Instagram 页面 UI 操作，不读取或上传账号凭据，也不调用 Instagram 私有 API。

功能范围如下：

- 只处理配置中指定的一条 Instagram 帖子或 Reels。
- 按删除关键词筛选已加载的子级回复，白名单和帖子作者始终优先保护。
- 只删除子级回复，不删除一级评论，避免未知级联回复造成误删。
- 扫描和删除当前评论容器中已经加载的内容；分页和自动滚动加载暂缓，由用户手动下滑后再次启动任务。
- 使用单线程调度、概率分布间隔、连续操作休息、全局限频和异常退避来控制删除节奏。
- 提供开始、预览、暂停、停止、状态、统计和暂停原因。

本期不实现 TikTok、YouTube、Facebook、跨帖子抓取，也不实现鼠标轨迹、浏览器指纹、User-Agent、Cookie、Session、CAPTCHA 或平台风控绕过。分页和自动滚动加载暂不启用，以避免误判 Instagram 动态评论容器、触发超出当前范围的网络加载或在未知页面结构下扩大删除范围。

### 当前加载范围（2026-08-24）

当前版本只扫描和删除启动时及任务运行期间当前评论容器中已经加载的评论/回复。代码中的分页与自动滚动实现已整体注释停用；任务在当前容器没有候选时完成。用户需要在 Instagram 页面手动下滑加载下一批内容，再点击“开始”或“预览模式”启动下一次扫描。这样可以把加载边界交给用户确认，待评论容器结构和分页行为稳定后再恢复自动化。

## 评论规则

### 目标帖子

只有当前页面规范化后的 URL 与配置目标 URL 完全相同时才运行。规范化忽略查询参数、哈希和末尾斜杠，但保留帖子类型和短代码；支持 `/p/<shortcode>/` 与 `/reel/<shortcode>/`。

### 白名单与关键词

- 白名单一行一个用户名，忽略大小写、首尾空白和可选的 `@` 前缀。
- 删除关键词一行一个普通文本；评论包含任一关键词即命中，匹配忽略大小写。
- 未配置删除关键词时，只扫描并展示候选数量，不删除任何评论。
- 白名单用户名的评论永不删除，即使文本命中关键词。
- 帖子作者自己的一级评论和回复永不删除，即使文本命中关键词。

### 一级评论与回复

只处理当前目标帖子评论区域中已经加载、或由用户手动下滑加载后可见的子级回复；一级评论始终只扫描和统计，不进入删除候选。

- 每次扫描优先展开可见的“查看回复/隐藏评论”等入口，再从结构化数据和可见 DOM 映射稳定评论 ID。
- 仅当子级回复命中关键词且不属于白名单或帖子作者时才加入候选；一级评论命中关键词也不得删除。
- 删除后必须确认目标回复已从 DOM 或结构化数据中消失，确认失败不得增加删除计数，也不得继续复用旧 DOM 节点。
- 扫描、删除和当前容器内的回复展开循环持续运行；当前容器没有待处理候选时认定任务完成。自动分页和滚动加载暂缓，用户手动加载后需重新启动任务。

如果 Instagram 菜单中没有可靠的删除项，说明账号没有对应权限或页面结构无法可靠识别；扩展必须暂停或跳过并记录原因，不得猜测或点击其他菜单动作。

## 操作节奏控制器

### 架构与模块边界

节奏控制器只接入现有删除路径：`scan() -> process() -> remove(candidate)`。评论规则、DOM 定位和 Instagram 页面操作保持独立。

- **配置模块**：提供默认值、旧设置迁移、规范化和校验。
- **延迟生成模块**：基于 Log-Normal Distribution 生成删除间隔和休息时间；内部保留 Gamma Distribution 的可替换实现。
- **状态机模块**：管理连续操作、休息、退避和暂停的转换；不直接依赖 DOM、Chrome 或定时器。
- **全局限频模块**：在后台 Service Worker 中维护所有 Instagram 标签页共享的每分钟和每小时操作额度。
- **内容脚本调度器**：负责等待、申请操作额度、调用 `remove(candidate)`、停止检查和面板状态更新。

建议模块文件为：

- `src/shared/action-pace-config.js`
- `src/shared/delay-generator.js`
- `src/shared/action-pace-controller.js`
- `src/shared/rate-limiter.js`
- `src/shared/backoff.js`

上述核心模块采用现有项目的全局脚本模式，以便同时被内容脚本、Service Worker 和不依赖浏览器的单元测试复用。

### 状态机

内容脚本现有的 `idle`、`scanning`、`running`、`cooling-down`、`paused` 和 `error` 继续作为界面运行状态。节奏控制器内部使用以下状态：

| 状态 | 含义 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| `NORMAL` | 准备处理下一条候选 | 会话启动、REST 或退避结束 | 获得操作额度后进入 `BUSY` |
| `BUSY` | 连续删除阶段 | 开始实际删除 | 成功后保持；达到连续上限进入 `REST` |
| `REST` | 阶段性休息 | 达到连续操作上限 | 休息结束后重置计数，进入 `NORMAL` |
| `BACKOFF` | 临时错误后的退避 | 可恢复错误发生 | 等待结束后进入 `NORMAL`；达到失败上限则暂停 |
| `PAUSED` | 不再自动操作 | 不可恢复异常或失败次数超限 | 用户手动重新开始 |

状态规则：

- 首条删除不额外等待删除间隔，但仍必须申请全局操作额度。
- 每次成功删除后增加连续操作计数，并清零连续失败计数。
- 连续操作数达到 `maxConsecutive` 后进入 `REST`；当前的 `batchLimit` 迁移为这个统一含义。
- 失败后清零连续操作计数，避免恢复后立即连续操作。
- 达到 `maxConsecutive` 后按休息最短/最长边界随机等待，休息结束自动继续；该上限表示每轮最多删除条数。
- 用户点击暂停时，立即取消操作间隔、REST、限频等待或退避等待，保留候选和统计并释放锁；再次点击开始（按钮显示“继续”）会重新扫描后恢复。
- 用户点击停止时，立即取消等待、清空当前候选并终止本轮任务；停止后再次开始会创建新会话。
- 失败达到上限后进入 `PAUSED`，必须由用户点击开始重新创建会话。
- 删除成功后必须回到 `scan()` 重新定位候选，不得沿用删除前的元素引用；每个稳定评论 ID 在同一会话中最多成功处理一次。
- 当前容器没有候选时直接完成；不执行自动分页或滚动。用户手动下滑加载后重新启动，任务会重新建立扫描集合。
- `sessionLimit` 设置为“不限”时不因累计删除条数停止；仍受每分钟/每小时限频、会话最长时间和不可恢复异常约束。

### 延迟生成

删除间隔与 REST 时间默认使用 Log-Normal Distribution，而不是简单的 `random(min, max)`。

每个延迟配置都包含：平均等待时间、最短等待时间、最长等待时间和变化程度。内部使用：

```text
mu = ln(mean) - sigma^2 / 2
delay = exp(mu + sigma * normalRandom())
```

其中 `normalRandom()` 使用 Box-Muller 方法生成正态随机数。生成值最多重采样 16 次；最终始终限制在最短和最长等待范围内，防止异常过短或过长。

页面同步等待不属于操作节奏：展开回复与悬浮菜单仍保留固定短等待，用于等待 DOM 更新；删除菜单出现后到点击删除按钮前的等待改为可配置的随机分布，既不消耗操作次数额度。

### 全局 Rate Limiter

全局限频使用后台统一的双滑动窗口算法，所有目标帖子和 Instagram 标签页共享同一额度。

1. 内容脚本在每次实际删除前向 Service Worker 发送 `ICC_RATE_ACQUIRE`。
2. 后台清理超过 60 秒和 1 小时的操作时间戳。
3. 两个窗口均未达上限时，记录当前时间戳并授权本次操作。
4. 任一窗口已满时，返回准确的 `retryAfterMs`；内容脚本等待后重新申请。
5. 操作额度在实际尝试删除前消耗；预览和扫描不消耗额度，失败重试会消耗额度。
6. 时间戳状态保存到 `chrome.storage.local`，Service Worker 重启后仍然有效。

默认上限：每分钟 5 次、每小时 60 次。

目标帖子锁继续按 URL 维持单实例。由于休息和退避可能超过现有 90 秒租约，内容脚本在运行期间每 30 秒发送 `ICC_RENEW_LOCK`；停止或暂停时清理心跳并释放锁。

### 异常退避

可明确判断为临时的页面、网络或浏览器交互错误使用指数退避；平台挑战、验证、限流提示、权限不足、删除菜单或确认按钮无法可靠识别时，仍直接暂停，不自动猜测重试。

退避公式：

```text
baseDelay = min(maxBackoff, baseSeconds * 2^(failureCount - 1))
actualDelay = baseDelay * (0.75 + random() * 0.5)
```

默认行为：首次等待约 30 秒，之后逐次翻倍，最长 15 分钟，连续失败 3 次后暂停。等待中的少量变化（Jitter）固定由内部安全配置管理，不要求用户理解或设置术语。退避结束后重新扫描并重新定位候选元素，不复用可能失效的 DOM 节点。

## 运行流程

```text
开始 / 预览
  -> 校验目标 URL、配置和页面异常提示
  -> 获取目标帖子锁并启动锁续租
  -> 展开入口并扫描当前已加载评论和回复
  -> 预览：显示候选统计后结束
  -> 正式运行：操作间隔 -> 申请全局额度 -> 删除子级回复
  -> 成功确认：计数、记录 ID、重新扫描并重建候选队列
  -> 当前容器为空：完成（用户手动下滑后重新开始）
  -> 临时失败：BACKOFF 后重新扫描
  -> 不可恢复错误或失败次数超限：PAUSED
  -> 当前评论容器无候选：完成（手动加载后重新开始）
  -> 结束/停止：取消等待、释放锁、保存状态
```

一次正式运行的示例：

1. 用户配置“每次操作大约等待 18 秒，范围 12-30 秒；连续处理 3 条后休息”。
2. 首条候选申请到全局额度后执行删除。
3. 下一条前生成例如 17 秒等待，等待后再申请全局额度。
4. 连续成功删除第 3 条后进入 REST，生成例如 165 秒休息时间。
5. REST 完成后重置连续计数，重新扫描并继续。
6. 如果分钟或小时额度已满，则自动等到后台返回的可用时间，不继续点击页面。
7. 临时错误进入退避；连续失败 3 次或出现验证、限流、权限、DOM 异常时，显示“已暂停”和原因。
8. 当前容器删除完后不刷新页面，也不自动滚动；用户手动下滑加载下一批后重新开始任务。

## 设置页设计

设置页采用“基础设置 + 高级设置”结构。普通用户不会看到 `Log-Normal`、`Gamma`、`sigma`、`Jitter` 或 `Token Bucket` 等技术术语。

### 基础设置

**操作节奏**

- `每次操作大约等待多久（秒）`：对应平均删除间隔；提示“系统会在此时间附近等待，不会每次完全一样”。
- `最短等待时间（秒）` 与 `最长等待时间（秒）`。
- `等待时间变化`：`较稳定`、`适中（推荐）`、`变化较大`。
- `删除前等待大约多久（秒）`、`删除前等待最短时间（秒）` 与 `删除前等待最长时间（秒）`。
- `连续处理多少条后休息`：取代“每轮最大删除数”。
- `每次休息大约多久（秒）`。
- `休息最短时间（秒）`、`休息最长时间（秒）` 与 `休息时间变化`。

**本次任务限制**

- `本次最多删除多少条评论`。
- `本次最多运行多久（分钟）`。

### 高级设置（默认折叠）

**操作次数上限**

- `1 分钟内最多操作多少次`。
- `1 小时内最多操作多少次`。
- 提示：`所有打开的 Instagram 标签页共用此上限。`

**遇到临时问题时**

- `第一次重试前等待多久（秒）`。
- `最长重试等待时间（秒）`。
- `连续失败多少次后暂停`。
- 提示：`每次重试的等待时间会逐渐变长，并带有少量变化。`

高级区域标题应显示当前摘要，例如“当前：每分钟 5 次、每小时 60 次、失败 3 次后暂停”。

内部配置集中保存为：

```text
pace.operation: { distribution, meanSeconds, minSeconds, maxSeconds, variability }
pace.rest: { distribution, meanSeconds, minSeconds, maxSeconds, variability }
pace.maxConsecutive
pace.rateLimit: { perMinute, perHour }
pace.backoff: { baseSeconds, maxSeconds, jitterRatio, maxFailures }
```

旧设置兼容规则：旧的删除/冷却最小最大时间分别迁移为操作/休息范围；平均值取范围中点；`batchLimit` 迁移为 `maxConsecutive`；等待时间变化默认为“适中”。保存时必须校验时间均为正数、最短值不大于最长值、平均值位于范围内，且操作次数和失败次数至少为 1。

## 交互与安全

设置页提供目标帖子 URL、白名单、删除关键词和上述节奏设置；“预览模式”只扫描与统计候选，不申请操作额度、不进入删除菜单。

Instagram 目标页注入 Shadow DOM 控制面板，显示当前运行状态、扫描数、删除数、跳过数、已加载回复数、当前等待原因、下一次可操作时间和最近错误。配置页点击开始后，目标页面加载完成即自动启动；删除流程自动处理页面确认，不再要求用户二次点击。任务完成时显示完成原因。自动分页和滚动加载停用期间不显示滚动轮次或空轮次数。

Instagram 界面会随语言和版本变化。评论、更多操作、删除菜单和确认弹窗的选择器应集中在 Instagram 适配器中，优先使用 ARIA 标签、角色和稳定的可见文本候选；找不到可靠元素时暂停，不使用宽泛选择器。

### Windows Chrome 运行约束

- 正式运行环境为 Windows 桌面版 Chrome；页面操作只使用 MV3 内容脚本可用的标准 DOM API、`scrollIntoView`、`MutationObserver`、`requestAnimationFrame` 和 Chrome Extension API，不依赖 macOS 快捷键、AppleScript、系统路径或触控板手势。
- 菜单定位不能假设鼠标悬停一定触发：定位后按 Windows Chrome 常见顺序派发 `pointerover`、`mouseover`、`mousemove`，显式聚焦并点击，再验证菜单实际出现。
- 展开、菜单、确认和删除结果均使用“页面状态变化或明确超时”的可取消等待；不能用固定短延时假设 Windows 网络和渲染速度。自动滚动加载相关等待已注释停用。
- 自动滚动容器识别和分页请求暂不执行；用户负责手动下滑，扩展只处理手动加载后当前容器中的结构化数据。
- Windows Chrome 页面结构、权限或语言无法可靠识别时必须暂停并显示原因，不得猜测点击或误判完成。

## 测试与验收

使用 Node 内置 `node:test` 编写纯算法单元测试，不引入第三方测试依赖。

1. 延迟生成值始终位于最短/最长范围内，样本平均值接近设置值，变化档位影响离散程度。
2. NORMAL、BUSY、REST、BACKOFF 和 PAUSED 的状态转换正确。
3. 连续操作达到阈值后必定 REST，REST 结束后连续计数重置。
4. 成功会清零失败次数；失败达到上限后进入 PAUSED。
5. 退避按指数增长、受最大值限制，并含有限范围的变化。
6. 多标签页并发申请时，每分钟和每小时窗口均不会超额。
7. 预览和扫描不消耗操作额度；限频状态持久化恢复后仍正确限制。
8. 停止操作会阻止任意等待结束后的下一次删除。
9. 配置迁移、中文字段校验与非法范围拒绝保存均正确。
10. 当前 URL 不匹配、关键词为空、验证页、限流提示、权限不足或 DOM 结构异常时，不产生不可靠删除操作。
11. 一级评论永远不进入删除候选；子级回复删除成功后会重新扫描，已处理 ID 不重复。
12. 回复展开、当前容器完成和手动停止均能正确转换状态，不刷新页面；自动分页和滚动加载保持停用。
13. 在 Windows Chrome 100%、125%、150% 缩放及较慢网络下，当前已加载容器中的删除确认超时不增加计数并安全暂停。
